# 章节拆分:超长稿重构为多章

> 用法:单章字数远超目标(如 10000-20000 字,目标约 4000 字/章)时,按自然断点拆成多章。
> 拆分不是剪切,是重构——每章必须成为独立的叙事单元:有完整前情承接、自己的情绪弧、章末钩子、构师备注。

## 核心原则

1. **断点由叙事决定,不由字数决定**。先找故事的自然断裂处(场景切换/时间跳跃/情绪节点/视角转换/动作停顿),再检查字数是否落在目标区间。严禁按字数机械切段。
2. **拆完的每章必须自成一体**。单看一章:前情提要给够承接,章末钩子给足翻页欲。
3. **正文一个字不改**(除非发现原稿错误)。拆分只负责切分、命名、补头部(前情提要)、补尾部(钩子)、补备注。不在拆分时改写正文。
4. **章名必须两字以上**,且不得与设定中的既有概念撞名。
5. **跨章衔接是拆分的生命线**:第 N 章章末钩子 → 第 N+1 章前情提要 → 第 N+1 章正文首句,三者必须无缝咬合。

## 操作流程

### 第一步:字数盘点与目标确认

用 CJK 正则统计每章正文字数(排除 Markdown 头部、前情提要、备注区):

```bash
# PowerShell 示例:统计单章 CJK 字数
$cjk = ([regex]::Matches((Get-Content -LiteralPath $file -Raw -Encoding UTF8), '[\u4e00-\u9fff]')).Count
```

- 识别哪些章超长(远超目标字数)
- **与用户确认**:目标字数/章(常见 4000)、成章硬底线(常见 ≥3500)、章名风格(两字/多字、是否含设定词)
- 字数是软参考,叙事断点是硬依据——断点落点优先于字数对齐

### 第二步:断点选取

候选断点优先级(从高到低):

1. **场景切换**:地点变化、视角角色变化、时间跳跃(昼夜/片刻之后)——最优断点
2. **情绪节点**:一次高潮结束后的余韵处、情绪转折完成处
3. **叙事停顿**:一个动作/事件的自然收束("她阖上眼""他走远了")
4. **原稿已有钩子**:原稿中已存在的悬念句、转折句,优先在此断开
5. **对话回合结束**:一轮对话彻底结束后(慎用,对话中断开体验最差)

断点禁止:

- ❌ 动作进行中硬切(如"她转身就跑"刚写完就断章,下章被迫从动作中途接续)
- ❌ 对话进行中切断(除非制造悬念且下章立即接续)
- ❌ 情绪顶点正中切断(顶点是章末钩子,不是断点——断在顶点**之后**的回落处)
- ❌ 因果链中间切断("他举起刀"——读者还没看到结果就换章)

断点验证:选中断点后,读取断点行号**前后各 1-2 行**,确认:

- 断点前的最后一句是完整句(不是半句)
- 断点后的第一句能独立作为新章开头
- 断点处存在一个"让读者想翻页"的余味或悬念

### 第三步:章名与撞名检查

- **两字以上**(用户常见硬性要求禁止单字章名)
- **撞名检查**:章名不得与世界观中的专有概念同名或高度近似。实例教训:设定中"旧账"是花宗线的专有概念,若用作第一章章名,会与后续花宗线"旧账"情节混淆——章名撞设定概念会让读者产生错误的联想锚点。命名前检索设定文件,有冲突则换名
- 章名应概括本章**情绪或意象**,而非仅概括事件("秋深"优于"秋深了看账")

### 第四步:切分正文

按断点行号切分。保持原文件的行号引用(记录"L3-123 / L125-285"这类边界,便于核对)。每章头部格式:

```markdown
# 第X章 · 章名

> 前情提要:(2-4 句,从上一章结尾状态接续。首章写"本章为全书开篇,无前情提要。")

[正文]
```

前情提要规则:

- 只承接上一章结尾已发生的状态,不泄露本章将发生什么
- 用"现在,……开始了"式收尾句过渡到本章正文
- 不含对话、不含 Markdown 格式

### 第五步:章末钩子

每章末尾必须有钩子(首章如全书开篇可弱化)。钩子类型:

- 悬念("还有一匹狼——踏着云")
- 未完成动作("把她按下去")
- 转折预告("灯火好像暗了一暗")
- 认知反转(读者以为 A,实为 B 的暗示)

钩子写在正文最后一段的自然延伸处,不另起一段生硬拼接。

### 第六步:构师备注

每章正文之后追加"构师备注"(`## 构师备注` 或 `---` 分隔),供后续审查/写作调用。模板:

```markdown
## 构师备注
**章节定位**:[卷·章节位置]。承接《上章》"钩子句"→本章内容→章末钩子=……
**视角**:[视角规则]延续——[各视角角色]……切换断点独立成段,同段内不混人称。
**核心设计**:[本章叙事功能/铺垫/暗线]
**风格执行**:[风格要求];段落间空一行,无标题无编号。字数NNNN(≥3500成章线)。
### 衔接
- 前接:《上章》"钩子句"→本章开头"首句"(无缝)。
- 后接:ch-NNN(下一事件)→本章末"钩子句"。
```

备注区内容为创作元数据,不计入正文字数统计。

### 第七步:跨章衔接验证(必做)

逐对核对:

1. 第 N 章章末钩子的最后一句话 ↔ 第 N+1 章前情提要是否接得上
2. 第 N+1 章前情提要的收尾句 ↔ 第 N+1 章正文首句是否无缝
3. 视角连续性:上一章末尾的视角角色/人称,下一章开头是否合理延续(多视角作品尤须检查,禁止断点处视角悬空)

### 第八步:视角一致性验证

多视角作品拆分后重点检查:

- 视角切换断点是否仍然"独立成段"
- 同一段内是否仍不混人称(拆分可能破坏原有的段间视角过渡)
- 旁观视角(如密室旁观者)的锚点是否在拆分后依然成立

### 第九步:字数验证与归档

- 每章正文(备注前)≥ 成章底线(如 3500)
- 新章与旧源文件如并存易混淆,将旧源文件归档到独立目录(如 `xx_旧N章归档/`),保留可追溯性

## 执行陷阱(实测教训)

| 陷阱 | 说明 | 对策 |
|------|------|------|
| **heredoc 写入被过滤篡改** | 用 PowerShell `Add-Content` heredoc 追加备注时,内容过滤器会篡改敏感词(实例:某设定词→被改字、某器物名→被改字、伏笔→段置) | 用 `edit` 工具逐处修正,或写完后全文扫描篡改词并修正;不要用 heredoc 反复重写整段 |
| **字数统计口径不一致** | 全文 CJK 计数包含标题/前情提要/备注 | 统计"正文(备注前)"口径,且核对含头部后的总数是否仍达标 |
| **断点行号引用错误** | 数组索引与行号差 1(如 `$lines[2..156]` 是 L3-157) | 切分时记录确切行号区间,验证首尾句 |
| **旧文件与新章撞名** | 旧 `第四章_活着.md` 与新 `第九章_活着.md` 同名混淆 | 先归档旧文件再建新章,或新章用不同名 |

## 反模式

- ❌ 按字数机械切段 — 断点必须由叙事决定
- ❌ 拆分时改写正文 — 只切分、命名、补头尾与备注
- ❌ 章名撞设定概念 — 命名前查设定文件
- ❌ 单字章名 — 用户常见硬性要求两字以上
- ❌ 跳过跨章衔接验证 — 钩子→提要→首句必须逐对核对
- ❌ 拆完不归档旧稿 — 新旧并存会污染后续流程的读取范围
